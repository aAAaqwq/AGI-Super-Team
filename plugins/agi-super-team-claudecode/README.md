# AGI Super Team for Claude Code

This package carries the **Claude Code-specific layer** only: one
`.claude/agents/ast-*.md` per canonical role plus the `agi-super-team-orchestrator`
Skill. It intentionally does not ship a copy of the canonical `skills/` tree --
see "Why there are no Skills here" below.

## Install

Through Claude Code's own marketplace, from the repository root:

```bash
claude plugin marketplace add ./            # this checkout
claude plugin install agi-super-team-claudecode@agi-super-team
```

Or reach the same 14 agents through the generic installer, which is the primary
route and also vendors the canonical Skill bodies:

```bash
npx -y agi-super-team@latest --tool claude-code            # preview
npx -y agi-super-team@latest --tool claude-code --install  # apply
```

## What is inside

| Path | What it is |
|---|---|
| `.claude/agents/ast-*.md` | 14 canonical roles (CEO, eight C-suite managers, PE, Governor) with Claude Code frontmatter |
| `.claude/skills/agi-super-team-orchestrator/SKILL.md` | the entry Skill that decides whether to assemble a team |
| `.claude/agi-super-team/connection.json` | the connection spec: `agentMap`, `managerAgentMap`, per-manager delegation, and the clean-client receipt checklist |

The C-suite managers are the eight outcome owners; the eleven executive
managers that own specialist pyramids are **not** installed by this package,
because those pyramids are 92 vendored third-party roles. Install them with
`npx -y agi-super-team@latest --tool claude-code --all-subagents --install`.

## Why there are no Skills here

A curated package cannot reference canonical content by relative path: Claude
Code rejects `..` in a component path, a symlinked `skills/` is not followed,
and `npm pack` drops symlinked directories entirely. The only way to ship
Skills would be to copy them -- 495 Skill directories, roughly 68 MB -- into
this package, and then again into each of the other harness packages. That is
canonical source duplicated four times to satisfy a layout, which
[ADR-0002](../../docs/adr/0002-generic-workspace-and-curated-distributions.md)
rules out.

So the package ships the harness-specific layer and leaves the Skill bodies to
the installer, which vendors them from the single `skills/` root. The
orchestrator Skill is included because it is generated per harness rather than
copied, and without it there is no entry point.

## Evidence boundary

Package structure is covered by `tests/test_claudecode_package.py`, including a
`--check` assertion that the generated bytes still match `bin/adapters/claude-code.mjs`.

That proves the package is **structurally** sound and in sync with its renderer.
It does **not** prove a current Claude Code client loads it. `connection.json`
carries `runtimeEvidence: "pending"` and the receipt checklist; do not describe
this package as verified until a revision-matched receipt passes.
