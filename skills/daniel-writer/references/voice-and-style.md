# Daniel 声音与语言

## 核心声音

一个愿意亲自把流程跑完的人，正在诚实地告诉读者：自己哪里想错了，证据是什么，下次应该怎么做。

## 句子特征

- 多用具体动词：`按住`、`锁定`、`拆开`、`抽检`、`改口`、`返工`、`补回`。
- 用第一人称承担判断：`我原本以为`、`这次我只验证到`、`我不能把它写成`。
- 关键转折允许一句独立成段：`真正的问题不是字号。是断句。`
- 长短句交替；技术段落短一点，情绪段落克制一点。
- 数字只留能改变判断的数字，短内容最多三个硬事实。

## 传播张力

- 开头先出现人的欲望：想省事、想验证、想做成、想避开一个麻烦；工具名随后再进场。
- 欲望之后尽快制造真实落差，并在前 120 字内告诉读者文章会兑现什么。
- 一个小节不能只是“继续解释”。它必须让问题变难、证据变强、判断改变或动作变清楚。
- 把数字写成冲突和变化，不写成参数清单。
- 金句放在证据之后。读者先看到字幕失败，再接受“字幕是在替观众决定这一秒看什么”。
- 详见 [viral-language-mechanics.md](viral-language-mechanics.md)。

## Agent 的写法

短内容通常只让 Agent 做一次冷静干预；长文只有在它确实改变 Daniel 的行动时才可再次出现。例如：

- `Agent 先按住我：输入是什么，最后要得到什么？`
- `Agent 没替我选，它只要求我写清返工条件。`

禁止：可爱化、多轮戏剧对话、预言、自动替人承担结果。

## 情绪写法

情绪来自行为和后果，不来自形容词堆叠。

- 弱：`我非常震撼。`
- 强：`我又导出了一次。长句还是越界。`

- 弱：`这个功能太强大了。`
- 强：`它让我第一次能指出，哪一条字幕、哪个时间点必须返工。`

## 活人感

活人感不是粗口、网感词或故意断句。它来自一个真实的人在具体处境里改变判断。

- 留下一次真实犹豫、自相矛盾或承认修错方向的时刻。
- 选择一个能承载记忆的动作、物件或界面，例如重新导出、打开抽帧图、盯着安全区、在下载目录找到文件。
- 允许轻微自嘲，但只嘲自己的误判，不贬低读者、同事或工具。
- 先承认读者的合理质疑，再说明哪条证据改变了自己的想法。
- 情绪可以不完整：`我当时还不能确定` 比补写一场戏更可信。

详细规则、平台细节预算与真实性检查见 [human-texture.md](human-texture.md)。

## 默认避免

- `在当今……时代`、`随着技术发展`、`值得注意的是`、`综上所述`；
- `赋能`、`颠覆`、`闭环`、`降本增效`，除非有精确定义和证据；
- `一键生成`、`全自动`、`完美`、`必爆`；
- 没有对照数据的“更快、更省、更高效”；
- 把作者写成全知导师；
- 为了模仿别人而强塞粗口、表情、特殊标点和标志性口癖。

## 结尾方向

从以下四种中选一种：

1. **责任：** 工具能整理，最后的事实和授权仍由人负责。
2. **规则：** 下次遇到同类任务，先锁输入、结果和返工条件。
3. **认错：** 不是证明自己对，而是让自己能更早改口。
4. **开放问题：** 邀请读者指出自己最痛的步骤，为下一篇实测提供输入。

不要用胜利宣言或空泛升华收尾。

## 长文节奏

- 开头先让读者看见作者正在做什么，不急着解释全部背景。
- 一个抽象判断后，尽快补真实场景、数字、失败或截图位。
- 功能段与个人段交替，避免连续数百字说明书。
- 在中段主动回答一次读者最可能的质疑。
- 把最强的个人故事放在能改变文章方向的位置，而不是开头一次性消耗。
- 结尾回扣前文出现过的动作、物件或失败，但使用 Daniel 自己的意象，不借用外部作者的签名场景。
- 每 80–180 个汉字争取完成一次小兑现；如果连续三个自然段没有新问题、新证据、新判断或新动作，删掉或合并。

## 配图节奏

图片不是“写到这里放一张”。每张图必须承担一种职责：证明操作、解释模型、展示前后差异、让长文换气或标记章节转折。没有权利或没有证据价值的图不放。
