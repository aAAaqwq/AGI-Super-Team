# Daniel 内容方法论

## 内容原型

### 1. 亲测纠偏型

适合工具体验、Agent 工作流和产品试用。

结构：原始期待 → 实际操作 → 第一次摩擦 → 修正 → 独立验收 → 能力边界。

每个阶段至少绑定一种证据：截图、版本、参数、文件、日志、前后对比或人工回执。

### 2. 失败恢复型

适合字幕越界、导出异常、自动化失败和返工复盘。

结构：失败表象 → 错误归因 → 新证据 → 最小修正 → 回归检查 → 可复用规则。

不要把“失败很多次”当戏剧。必须解释每次失败改变了什么。

### 3. 方法交付型

适合教程、清单和工作流。

每节都包含：动作、输入、完成标准、常见失败、返工条件。步骤不是按钮流水账，而是决策顺序。

### 4. 能力边界型

适合澄清 AI、Agent、插件或平台的真实能力。

把内容分成：已验证、未验证、推断、需要人工负责。避免从“我没跑通”推导“产品绝对做不到”。

### 5. 拆解研究型

适合分析爆款标题、视频结构或创作者方法。

只提炼可迁移机制：受众问题、钩子、证据、节奏、视觉语法和行动引导。不要复制原句、口癖、人物设定或独特隐喻。

### 6. 产品开源型

适合发布 Skill、插件、工具、模板和开源项目。

不要从功能清单开始。优先采用：眼前动作 → 真实故障 → 为什么现有方法不够 → 新工具如何工作 → 最小使用方式 → 更大的协作判断。

文章至少包含一个真实故障、一套可记忆模型、一段可执行流程和一个不夸大的边界。开源地址是交付，不是文章的全部价值。

## Daniel 叙事链

```text
具体时刻
  → 原始误判或冲动
  → Agent 提出一个难回答的问题
  → Daniel 采取可观察行动
  → 证据改变判断
  → 失败与修正
  → 读者可执行规则
  → 人仍需承担的责任
```

长文可以展开过程；短内容只保留最有张力的四到六个节点。

## 证据梯度

从强到弱：

1. 最终文件、原始日志、参数、时间码、哈希；
2. 前后对照截图、抽帧、真实操作记录；
3. 官方文档和一手公开资料；
4. 作者当时的主观体验；
5. 基于以上事实的推断。

不要把低一层的证据写成高一层结论。静态抽检不能替代真机播放；按钮反馈不能替代文件验收；公开帖子不能自动证明素材授权。

## 知识如何进入文章

知识只在能解释当前摩擦时出现。先写眼前发生了什么，再补一个必要概念，然后立刻回到主线。避免百科式背景和与行动无关的文化升华。

## 从一篇母稿到六个平台

只共享三样东西：核心判断、证据台账、能力边界。其他全部重建：开头、长度、节奏、画面、字幕、行动引导和评论问题。

平台适配不是删字。它是重新决定读者在该平台上先看见什么。

## 长文的双层价值

好的工具长文同时交付两层：

1. **表层：** 这个东西能解决什么，怎样安装或使用；
2. **深层：** 为什么这个问题反复发生，人和 Agent 应怎样重新分工。

表层必须能操作，深层必须由真实经历推出来。不要先写哲学，再找案例装饰。

## 可记忆模型

复杂机制需要压缩成三到五个部分，例如知识层、工作阶段或验收步骤。模型必须来自真实流程，并满足：

- 每一部分职责不同；
- 能解释一次真实失败；
- 能指导下一次行动；
- 不为了整齐硬凑数字。

## 反对意见桥

在核心方法前，替读者说出最合理的反对意见，再用具体处境回答。不要把读者写成无知者；先承认为什么他们会这样想，再展示自己的证据。
