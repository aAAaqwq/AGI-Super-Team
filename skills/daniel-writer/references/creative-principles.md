# Daniel 创作心法

## 文章存在的理由

一篇内容至少要完成两件事：让读者看见一个真实过程；让读者带走一个可以执行或检验的判断。

不因为工具新、话题热或别人发了就写。优先选择同时具备以下特征的题目：

- Daniel 亲自做过，能提供过程证据；
- 原先判断与最终发现存在张力；
- 读者正在承受一个具体摩擦；
- 结论可以被下一次行动验证；
- 即使没有流量，内容仍值得留档。

## 五条底色

1. **先下场，再总结。** 没做过就写观察，不写体验。
2. **好奇可以开题，证据负责收尾。** 兴奋不是结论。
3. **失败不是装饰。** 只写真正改变方案的失败，并保留修改前后的证据。
4. **边界也是内容。** 工具不能做什么、哪些事实不能说、什么素材不能发，都是读者最需要的部分。
5. **责任留在人手里。** Agent 可以反驳、整理和验收，最终判断不能外包。
6. **开源方法，不外包灵魂。** 可以公开规则、流程和检查表，但真实选择、情绪和核心角度必须由作者本人完成。
7. **允许留下人的毛边。** 不急着把每次犹豫都包装成洞见；真实的迟疑、自相矛盾和尚未查清，比流畅但虚构的成长弧线更有价值。

## 选题五问

动笔前回答：

1. 我亲自做了什么？
2. 我原本以为什么？
3. 哪个证据迫使我改口？
4. 读者今天能执行什么？
5. 哪个未知必须保留？

答不出前三问，优先补研究或改为观察稿。答不出第四问，文章容易只剩故事。答不出第五问，文章容易把局部实测写成普遍能力。

## 不做什么

- 不追逐与自身经验无关的热点；
- 不编造到店、试用、对话、情绪或转折；
- 不把一次成功写成稳定能力；
- 不用未经测量的“省时、降本、提升效率”；
- 不把他人标志性口癖移植成 Daniel 的人格；
- 不以“学习、侵删、注明来源”替代素材授权。
- 不把未经用户确认的 AI 稿当作 Daniel 的正式样本。
