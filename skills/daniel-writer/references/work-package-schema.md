# 内容工作包规范

## 目录契约

| 文件 | 作用 | 完成标准 |
|---|---|---|
| `00-brief.md` | 受众、目标、平台和边界 | 不存在未解释的关键空项 |
| `01-evidence-ledger.md` | 主张与证据映射 | 每个发布级事实都有稳定 ID 和来源 |
| `02-story-map.md` | 跨平台母故事 | 关键节点引用证据 ID |
| `deliverables/*.md` | 平台原生稿 | 结构、语气、CTA 与平台匹配 |
| `99-publish-checklist.md` | 发布前人工闸门 | 高风险项均有明确结论 |
| `manifest.json` | 机器可读索引 | 平台与文件一一对应 |

## 证据等级

- `直接`：代码、项目文档、可重放命令输出或用户明确确认直接支持。
- `推断`：由多个事实合理推导；发布时必须表述为分析或判断。
- `待确认`：缺少足够证据；不得作为确定事实发布。

推荐证据行格式：

```text
| E-001 | 项目采用静态站点输出 | README.md:18 | 直接 | 可公开 | - |
```

证据位置优先使用可定位路径与行号；临时命令输出应保存摘要和复现命令，不粘贴敏感原文。

## 平台结构

### wechat

标题备选 → 开场问题 → 背景与约束 → 分步方法 → 证据化案例 → 清单/总结 → CTA。适合完整解释和搜索沉淀。

### xiaohongshu

封面文案 → 结果或痛点钩子 → 3–7 个要点 → 配图/卡片说明 → 风险提示 → 收藏型 CTA。避免只复制长文摘要。

### douyin

前 3 秒钩子 → 问题 → 操作/演示节拍 → 证据画面 → 结论 → 单一 CTA。为每一拍标注画面、口播、字幕和预计时长。

### bilibili

学习承诺 → 章节 → 环境/前提 → 完整演示 → 常见错误 → 复盘 → 资料说明。所有跳步都要解释输入与输出。

### generic

当平台不在上述列表时，创建：受众与场景 → 原生格式约束 → 内容结构 → 素材清单 → CTA → 风险。

## 发布验收

- 抽查所有数字、比较级、结果和引用能否回到证据账本。
- 删除密钥、真实个人信息、内部 URL、未授权截图和第三方受限素材。
- 确认视频稿包含字幕文本，图文稿包含图片替代说明或可理解的文字说明。
- 确认每个平台有独立钩子、信息密度和 CTA。
- 将未完成项保留为显式 TODO，不用貌似合理的内容填空。
