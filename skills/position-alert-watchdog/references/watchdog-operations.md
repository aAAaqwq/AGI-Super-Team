# 盯盘运维手册（日K 多源、话术、竞价 cron、通用配方）

## 日K 多源 fallback（2026-10-30 踩实）

**腾讯日K接口 `web.ifzq.gtimg.cn/appstock/app/fqkline/get` 曾整段返回 `HTTP 501 Not Implemented`**，
带不带 SSL context、换 UA、换 Referer 全都 501 —— 不是参数问题，是端点本身不可用。
**症状**：盯盘脚本静默失效（`kline()` 抛异常 → 所有 MA/昨高低算不出来 → 规则全不触发）。
**注意**：分时接口 `appstock/app/minute/query` 当时仍然正常，坏的只是 **fqkline** 这一个端点。

**修复：`kline()` 写成「东财为主、新浪为备」的双源**（腾讯不再作为主源）：

```python
def kline(code, n=90):
    """返回 [{"d","o","c","h","l","v"}]，v 单位 = 手。东财主源，新浪备源。"""
    c6 = code.split(".")[0]
    secid = ("1." if c6.startswith("6") else "0.") + c6

    # 主源：东财 push2his —— 字段顺序是 日期,开,收,高,低,量(手),额
    try:
        u = ("https://push2his.eastmoney.com/api/qt/stock/kline/get"
             f"?secid={secid}&fields1=f1,f2,f3,f4,f5,f6"
             f"&fields2=f51,f52,f53,f54,f55,f56,f57"
             f"&klt=101&fqt=1&end=20500101&lmt={n}")
        kl = (json.loads(http(u)).get("data") or {}).get("klines") or []
        if kl:
            out = []
            for s in kl:
                p = s.split(",")          # ⚠️ 开,收,高,低 —— 不是 OHLC！
                out.append({"d": p[0], "o": float(p[1]), "c": float(p[2]),
                            "h": float(p[3]), "l": float(p[4]), "v": float(p[5])})
            return out
    except Exception:
        pass

    # 备源：新浪 CN_MarketData —— volume 单位是「股」，要 ÷100 转手
    try:
        sym = ("sh" if c6.startswith("6") else "sz") + c6
        u = ("https://money.finance.sina.com.cn/quotes_service/api/json_v2.php/"
             f"CN_MarketData.getKLineData?symbol={sym}&scale=240&ma=no&datalen={n}")
        d = json.loads(http(u))
        if d:
            return [{"d": x["day"], "o": float(x["open"]), "c": float(x["close"]),
                     "h": float(x["high"]), "l": float(x["low"]),
                     "v": float(x["volume"]) / 100} for x in d]
    except Exception:
        pass

    return None
```

**三个必须记住的差异**：

| 源 | 字段顺序 | 量单位 | 备注 |
|---|---|---|---|
| 东财 push2his | **日期,开,收,高,低**,量,额 | 手 ✅ | 主源，格式最清晰 |
| 新浪 | day,open,high,low,close,volume | **股（÷100）** | 备源 |
| 腾讯 fqkline | 日期,开,收,高,低,量 | 手 | 曾用主源，端点曾 501 |

**另外：东财 `secid` 前缀 —— 沪市 `1.`、深市 `0.`。指数 399006 属深市（`0.399006`），写 `1.399006` 返回 0 根。**

### ⭐⭐ 空 K 线必须全程容错，否则一次网络抖动 = 一次 cron 失败告警（2026-11-06 实踩）

脚本一度**回退成腾讯 fqkline 单源**（与本节写的「东财为主、新浪为备」不一致），11:00 那轮腾讯返回异常 →
`except` 把 `k=[]` → `levels()` 里 `ref = k[-1]` → **`IndexError: list index out of range`** → exit 1 →
用户收到「Cron 盯盘 failed: 盯盘脚本异常」。11:30 之后几轮又正常，**是瞬时故障，只看当前状态根本复现不出来**。

三层防护，缺一层都不行：

```python
# ① kline() 三源 + 永远返回 list（不返回 None）
for src in (dongcai, sina, tencent):
    try:
        ...; if len(k) >= 2: return k
    except Exception: pass
return []          # ← 空列表，不是 None（None 会在 len(None) 处变 TypeError）

# ② levels() 空 k 降级，不崩
if quoted_today and len(k) >= 2: ref = k[-2]
elif k:                          ref = k[-1]
else:                            ref = None
prev_high = float(ref[3]) if ref else prev      # 降级用昨收
prev_low  = float(ref[4]) if ref else prev
L[f"ma{n}"] = ma(k, n) if k else None           # MA 自动缺席 → 相关规则被 L.get() 跳过

# ③ main() 逐只票 try/except + 行情快照重试 2 次
raw = ""
for _ in range(2):
    try:
        raw = http(...);  break
    except Exception: raw = ""
if '"' not in raw: return        # 全挂 → 静默跳过本轮，不要 exit 1 刷故障通知
for line in ...:
    try:
        ...整只票的处理...
    except Exception as e:
        print(f"⚠️ {name} 处理异常({type(e).__name__}: {e})，跳过", file=sys.stderr)
        continue
```

**取舍**：行情源整体挂掉时**静默**比报错好（否则每 30 分钟一条 failed 通知）；真正的 bug 由 stderr + 后续人工发现。

### ⭐⭐ 只比对「现价」会漏掉瞬间穿越的关键位（同日实踩，代价是漏一次全清）

示例股A当日最低 **15.85 已跌破 16.08「全清」线**，但 13:30 轮询时现价已反弹到 16.34 → **`price <= 16.08` 判否 → 全清提醒从未发出**。30 分钟轮询必然漏掉这种「插针又拉回」。

修法：命中判定加一路「盘中曾触及」，且与 `fired` 分开存：

```python
hit = price >= lvl if op == ">=" else price <= lvl
if not hit:
    hi, lo = L.get("today_high"), L.get("today_low")
    if op == ">=" and hi is not None and hi >= lvl:  → touched 候选（取最高档）
    elif op == "<=" and lo is not None and lo <= lvl: → touched 候选（取最低档）
    continue
```

三条铁律：

1. **现价命中写 `state["fired"]`，盘中触及写 `state["notified_touched"]`** —— 绝不能混。若把"触及"记进 `fired`，
   后面价格**真的**跌破该档位时会被去重挡掉，等于把止损提示永久吞了。
2. **每只票每方向一轮只报最极端一档**（`>=` 取最高、`<=` 取最低），否则开盘跳空会一次刷 3-4 条同向提醒。
3. **同一方向的所有 touched 候选一起标记 `notified_touched`**，否则每轮会"滴漏"下一条（实测第二轮又蹦出百花 10.02、新经典 16.62）。

消息里必须写清是"现价"还是"盘中触及"：`（盘中触及 15.85，现价已回）` —— 否则用户会以为现价就在那儿。

## ⭐ 市场前缀补全必须幂等（2026-10-30 踩实）

写数据脚本几乎都会有个 `tc(code)` 补 `sh`/`sz` 前缀。朴素写法在**传入已带前缀的代码**时会拼出 `szsz399006`：

```python
# ❌ 传入 "sz399006" → "sz" + "sz399006" = "szsz399006" → K线永远拉不到
def tc(code):
    c = code.split(".")[0]
    return ("sh" if c.startswith("6") else "sz") + c

# ✅ 先判断是否已带前缀
def tc(code):
    c = code.split(".")[0]
    if c.startswith(("sh", "sz", "bj")):
        return c
    return ("sh" if c.startswith("6") else "sz") + c
```

**症状**：指数（399006）K线恒为 0 根，依赖它的「大盘环境检查」永远走 `数据不足，默认通过` 分支 —— **静默降级，不报错**，最难发现。
**自查**：写完 `tc()` 立刻 `print(tc("sz399006"), tc("002403"), tc("600698.SH"))`，三个都必须对。

## 减亏方案 → 重写盯盘规则（2026-10-29 实战）

用户问「最佳操作减少亏损」时，答案不是「每只都设止损」，而是**先排序、再重写规则**。排序维度必须是两个不是一个：

| 维度 | 算法 | 用途 |
|---|---|---|
| **亏额占比** | `单只亏损额 ÷ 总亏损额` | 找出「哪只在主导亏损」 |
| **风险信号数** | 利空条数（业绩/问询函/天量派发/破位…） | 找出「哪只最该先扔」 |

**两者经常指向不同的票，这是关键**：

```
实例（10/29）：
  示例股A  亏 −2,268 元 = 总亏损的 82%   ← 亏额占比最高，但有业绩 +97.52% 支撑
  示例股B  亏 −51 元（只 2%）           ← 亏额最小，但 4 个利空（天量4.9x派发 + 净利−37.65% + 问询函 + 冲高回落10.5%）

→ 结论：先清示例股B（用最小代价甩掉最大雷），超声减半（锁一半、留一半赌业绩）
```

**重写规则的模板（每只票四档必须齐全）**：

```python
"sh600000": {
    "name": "示例股B", "cost": 13.527,
    "rules": [
        (">=", 13.55,  "🟢 回到成本以上 → 立刻全清（亏51元甩掉业绩雷+问询函）"),
        (">=", 13.20,  "🟠 反抽 13.20 → 减半或全清"),
        ("<=", 12.76,  "🔴🔴 跌破今日低 → 立刻全清"),
        ("<=", "ma5",  "🔴 跌破 MA5（{v}）→ 无条件清"),
    ],
},
```

**四档的作用**：①回本/止盈档 ②反抽档 ③破位档 ④均线兜底档。
**缺任何一档都会出现「价格走到中间无规则可依」的空档**，而用户在盘中就是在等这一句话。

### ⭐⭐ 用户问「能不能做 T」时：先把账算给他（2026-11-12 实测，一次就把念头打断）

**深亏票做 T 是用户反复问、反复做反的动作。不要只讲「做 T 没用」，要给算式的结论。**

用户问「超声能做 T 卖点在哪」，实测数据：

```
当日振幅 1.28%（高 18.98 / 低 18.74）
可用 100 股 × 18.75 × 1.28% = 24 元
扣手续费（万三 6 元）+ 印花税（2 元）
────────────────────────
一次 T 净赚 ≈ 16 元；浮亏 1,891 元 ÷ 16 = 118 次
```

**➜ 结论话术：**「要连续做对 118 次 T 才回本 —— 这不是策略，是自我安慰。」

**三个必须一起给的数**：
1. **当日振幅**（做 T 的物理上限）
2. **一次 T 的净利润**（振幅收益 − 手续费 − 印花税）
3. **回本次数 = 浮亏 ÷ 单次净利**（这个数字通常大到荒谬，是最有说服力的一句）

**再补一句「按近 5 日平均振幅算」的对比**：超声近 5 日振幅 6.83/6.16/8.68/6.56/4.74，平均 6.6% → 一次净赚约 110 元，仍需 **17 次全对**。即使放宽到历史最好情况，答案依然是「不值得」。

**同时给正确动作**：深亏票不该做 T，该做「**反弹减仓**」——
冲前期高点减一半、破当日低再减一半、破前低全清。**这不是做 T，是止损离场。**
用户对「减仓」的接受度远高于「清仓」，所以话术要落在「减」而不是「割」。

**写给用户时必带三个数**：现价 / 盈亏% / **亏额（元）**。
只给百分比，用户无法判断「值不值得为这 50 块钱继续盯盘」；给出金额他才能决策。

### ⭐⭐ 回复长度纪律（2026-11-09 用户两次回「？」）

本会话每次「持仓分析」都写成 5-8 屏（多维度表 + 逐只长段 + 结尾 6 条编号「一句话」），
用户直接回「？」两次 —— **这不是要更多信息，是嫌太长**。

**规则**：
- **首屏就给结论**：哪只减、哪只留、什么价位，一张表说完。分析过程折到下面或直接省掉。
- **不要每次都以「💡 一句话」收尾再复述 6 条编号** —— 那是把同一段内容写两遍，纯噪声。
- **单次回复控制在 1 屏**（约 30 行）。用户想看细节会追问，追问时再展开。
- **删除装饰性标题**（`# 📊 XXX 多维度分析` + `>` 引用行 + 分隔线叠三层），只留必要的表和小标题。
- 用户已经在盯盘的票，**不要重复解释"为什么亏"** —— 他知道自己亏 27%，只需要「今天怎么办」。

**判断标准**：如果一条回复里「结论」需要滚屏才能看到，就已经太长。

**「减半」要连带说清留的那一半怎么办** —— 否则等于没建议：
> 「减半锁亏 −1,106，剩 200 股：反弹 17.50 清、跌破 16.40 走。」

## ⭐ 持仓「该不该减」的第四个维度：板块涨停数归零（2026-11-05 实战）

盯盘脚本只盯价格，但**决定要不要减仓的最硬信号往往不在价格上，而在「你那只票所在板块的涨停数」**。

### 每日必做（盘前 1 分钟）

```python
# 拉昨日涨停池，按 hybk（行业板块）统计
pool = zt_pool(date=yesterday)                       # push2ex getTopicZTPool
ind  = Counter(x['hybk'] for x in pool)
for pos in positions:
    n = sum(v for k,v in ind.items() if pos['sector_kw'] in k)
```

| 板块涨停数 | 判读 | 动作 |
|---|---|---|
| **≥5 只** | 有梯队，游资在做 | 可持有 |
| 3-4 只 | 弱梯队 | 只做龙头 |
| 1-2 只 | 独苗孤军 | 冲高减半，别指望次日 |
| **0 只** | **🚨 板块退潮** | **优先减仓，不要等反弹** |

### 看「变化」比看「绝对值」重要（实测）

| 持仓 | 板块 | 11/04 | 11/05 | 判读 |
|---|---|---|---|---|
| 示例股A | 元件 | **7 只** | **0 只** | 一天归零 = 退潮 |
| 百花医药 | 化学制药 | 1 只 | 0 只 | 一直没梯队 |
| 新经典 | 出版 | 2 只 | 0 只 | 弱转无 |

**当日全市场还有 84 只涨停（热点在光伏 11 只、半导体 4 只）—— 市场好，但你的板块被抽走了。**

**➜ 此时正确动作是「减掉走的」，不是「大盘涨我票跌所以要补」。用户在板块归零当天最容易问出这句，直接把这张表摊给他看。**

**反向用法**：0 → 1 → 2 的递增是板块启动早期信号，比单看个股形态可靠（配合龙头封单看）。

## ⭐ 隔夜外围 → A 股板块传导映射（决定「低开是跟跌还是错杀」）

用户早上问「今日操作建议」时，**先看隔夜外围再映射板块**，否则会把「板块被杀」当成「个股走弱」。

| 外围事件 | A 股承压板块 | 相对受益 |
|---|---|---|
| **纳指100 / 英伟达大跌** | **PCB / 元件 / 光模块 / CPO / 半导体 / 算力** | 医药、消费、公用事业（避险） |
| 费城半导体跌 | 半导体设备、封测、存储 | 国产替代（偶尔反向炒） |
| 原油大涨 | 航空、化纤、物流 | 油气、煤炭 |
| 黄金大涨 | — | 黄金股、贵金属 |
| 港股暴涨 + 韩股暴跌 | — | 「AI 叙事生变」，留意资金转港股 |

**实测（2026-11-05 隔夜 → 11-06）**：纳指100 **−6.5%**、英伟达 **−9%**、软银 −16%、韩国 KOSPI −6.8%（触发 SIDECAR）。东财标题：「**AI产业链遭重挫**」。

→ 示例股A（PCB，AI 服务器高频高速板）**直接吃杀，预计低开 3-5%**；
→ 百花医药（化学制药，与 AI 链无关联，且当日有医保钱包2.0/手术机器人/器械拐点等密集利好）**反而可能逆势**。

**同一个账户里两只票，隔夜外围给了完全相反的信号 —— 这是「分维度判断」而不是「一刀切」。**

## ⭐ 恐慌低开的操作纪律：9:30-9:45 不动

外围崩盘次日，用户会想「开盘先割」。**这是和「追高」对称的同类错误。**

**规则**：开盘 15 分钟是情绪最恐慌的时候，**先看承接再决策**。

| 时间 | 做什么 |
|---|---|
| 9:25 | 看竞价：各票低开/高开多少 |
| **9:30-9:45** | **不动**，看第一波杀跌后有没有承接 |
| 9:45-10:30 | 按反抽位/关键位执行（如反抽 MA5 不过 → 减半） |
| 14:30 | 若破当日低点 → 减半收工 |

**同时配合「已经深亏的票别在低开时割」**：亏 27% 的票再割在低开 -5% 处，是把「浮亏」变「实亏」的最差时点；等反抽位不过再减，同样降敞口但少亏 5%。

**话术**：用户自己踩过「追高亏 20%+」，用这个对称提醒他能立刻接受 —— 「追高和恐慌割是同一类错误」。

## 姊妹形态：竞价分析 cron（agent 模式，不是 no_agent）

盯盘是「**触发才响**」的 no_agent watchdog；**竞价分析是「每天必响一次 + 要判断」**，形态不同。

| 项 | 盯盘 watchdog | **竞价分析** |
|---|---|---|
| 模式 | `no_agent=true`（纯脚本 stdout） | **agent 模式 + `script`** |
| 频率 | `*/30 9-15 * * 1-5` | **`26 9 * * 1-5`**（9:25 定盘后 1 分钟） |
| 输出 | 有新信号才推，否则静默 | **每天必推一条分析** |
| 谁做判断 | 脚本里的阈值规则 | **LLM 按 prompt 里的规则表判断** |

### 结构：脚本取数 → agent 分析

```
cronjob(action="create", schedule="26 9 * * 1-5", script="auction_watch.py",
        deliverables="origin", enabled_toolsets=["terminal","file"], prompt=<规则表>)
```

- `script` 的 stdout 会**注入 agent prompt**，所以脚本只需输出结构化事实（现价/竞价幅度/关键位距离/外盘/板块梯队），**不要在里面写结论**。
- prompt 里要写死**判断规则表**，否则每天的分析口径会漂：

```
高开 >+3% 且无板块支撑 → 冲高减半
低开且破 MA5        → 减半
破止损位            → 全清
板块涨停 <3 只      → 无梯队，个股涨停也是孤军，次日易开板
板块涨停 ≥5 只      → 有梯队，可持有
外盘 <45%          → 主动卖多，偏弱
```

- prompt 末尾加一句「如果数据缺失或异常（比如竞价量为 0），直接说明，不要编造」。

### ⭐⭐⭐ 单一 JSON 数据源（2026-11-09 用户明确要求，取代旧的「改两处」做法）

**旧做法的痛点（用户原话：「有无专门地方记录我持仓股？我需要统一一个json文件改」）**：
持仓散落在 `watch_positions.py` 的 `WATCH` 字典 + `auction_watch.py` 的 `POSITIONS`/`KEY_LEVELS` + cron 的 prompt 文本里，
改一次要动三四个地方，必然漏改（本次实测：超声已卖 100 股剩 200，脚本里仍写 300，导致盈亏算错一整轮）。

**现行结构：`$AST_DATA_DIR/positions.json` 是唯一数据源，两个脚本都读它，cron prompt 不再写死持仓。**

```json
{
  "updated_at": "2026-11-09T08:50:00+08:00",
  "positions": [
    {"code": "000001", "sym": "sz000001", "name": "示例股A",
```

### ⭐⭐ 同一只票一轮只能推一条（2026-11-09 实测刷屏）

自动生成规则后，一只票可能**同时**满足「冲昨高→减半锁利」和「跌破 MA5→减半」，
两条都推出去等于给用户矛盾信号（既让止盈又让割肉）。

**去重口径：按股票名分组，只保留优先级最高的一条。**

```python
def _pri(a):
    if "全清" in a or "🔴🔴" in a:  return 3
    if "减半" in a or "清仓" in a:  return 2
    return 1                                   # 止盈/观察

_dedup = {}
for a in alerts:
    nm = re.match(r"【([^】]+)】", a).group(1)
    if nm not in _dedup or _pri(a) > _pri(_dedup[nm]):
        _dedup[nm] = a
alerts = list(_dedup.values())
```

**注意去重要在「所有 append 之后、输出之前」做** —— 脚本里有两条 append 路径（命中 `fired` 一条、盘中触及 `touch_pending` 一条），
只在其中一条里做局部去重会漏（本次实测第一次改就漏了，因为 touch_pending 单独 append）。

### ⭐⭐ 观察股的自定义关键位：JSON `rules` 覆盖自动生成（2026-11-12 实测）

自动生成规则只有三种（回踩 MA5 / 涨停 / 破 MA30），但**每只观察股的关键位各不相同**：

| 标的 | 该盯的价位 | 自动规则抓得到吗 |
|---|---|---|
| 示例股H | 放量突破 **4.20**（前涨停价） | ❌ 这是绝对价位，不是 MA |
| 思美传媒 | 封住 **6.59**（涨停价）才算转强 | ❌ `limit_up` 是当日涨停价，会随昨收变 |
| 中重科技 | 跌破 **4.02**（当日低）就放弃 | ❌ 当日低点不是 MA |

**解法：在 JSON 的观察股条目里加 `rules` 数组，脚本优先用自定义规则，没有才走默认。**

```json
{
  "code": "000005", "name": "示例股H", "stop": 3.86,
  "rules": [
    {">=": 4.20, "msg": "🟢 放量突破 4.20（11/09涨停价）→ 买点，1成仓，止损3.86"},
    {"<=": 4.02, "msg": "🔴 跌破 4.02（今日低）→ 放弃，移出观察"}
  ]
}
```

```python

if custom:
    for r in custom:
        msg = r.get("msg", "")
        for op, lv in r.items():
            if op in (">=", "<="):
                rules.append((op, lv, msg, "custom"))   # 4 元组 = 自定义

else:

```

### ⭐⭐⭐ 自定义规则必须跳过「盘中触及」兜底 —— 触及 ≠ 封住（同日实测误报）

脚本原有「盘中曾触及该档位也提醒」的兜底（防 30 分钟轮询漏掉插针）。
但把它套到自定义规则上就出事：

```
思美传媒 现价 6.35，当天最高 6.59（曾摸涨停但没封住）
→ 兜底逻辑判定「盘中触及 6.59」→ 推送「🔥 封住涨停 6.59 → 转强，可小仓跟」
→ 用户看到会以为已经封板了去追，实际只是插了一下就回来了
```

**根因**：兜底逻辑是为「跌破止损位」设计的（插针跌破也算风险，事后提醒合理）；
但对「封住涨停」这种**持续性状态**，触及一秒和封住全天是两回事。

**修法：自定义规则只看实时价，跳过兜底。**

```python
for rule in w["rules"]:
    is_custom = len(rule) == 4
    op, spec, msg = rule[0], rule[1], rule[2]
    ...
    if not hit:
        if is_custom:
            continue          # ← 自定义规则不做盘中触及兜底
        hi, lo = L.get("today_high"), L.get("today_low")
        ...
```

**通用教训**：兜底/补偿逻辑只适用于「瞬时穿越也构成风险」的条件（止损、破位）；
对于「达成某状态」的条件（封板、站上均线、连续 N 天），**绝不能加触及兜底**，否则把「碰过」报成「达成」。

## 通用配方：no_agent cron watchdog（可复用到别的监控）
`no_agent=true` + 脚本 + `state.json` + 动态阈值 + 只在新信号时 print，是这类"定时盯某指标、异常才喊人"任务的通用形态（同仓另有 `m6_supply_watch.py`/`m6_watch_state.json`、`newapi_report.py`）。要点：空输出即静默、错误走 stderr+exit 1、状态文件放脚本同目录、跨越交易日的时间 guard 写在脚本里而不是只靠 cron 表达式。
