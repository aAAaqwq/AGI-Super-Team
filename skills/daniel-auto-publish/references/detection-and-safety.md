# 检测面和账号安全边界

## 真实浏览器 Computer Use 改变了什么

可见的操作系统级或辅助功能输入，可以减少 Playwright、Selenium、注入脚本和无头浏览器关联的一部分明显 WebDriver/CDP 特征。普通浏览器档案还保留日常 Cookie、扩展、字体、历史记录和设备连续性。

这只是检测体系中的一层，不能让自动化隐形。

## 平台仍能观察什么

- 账号身份、账号年龄和历史处罚；
- IP/ASN、地区、网络变化和并发会话；
- 浏览器或设备指纹及跨会话变化；
- 登录、跳转、输入、上传和发布时序；
- 发布频率、集中爆发、重复排期和多账号关联；
- 重复媒体、感知哈希、模板化文本和重复元数据；
- 内容、版权、商业、原创和 AI 声明是否合规；
- 挑战失败、重复提交和创作者页面异常；
- 无论鼠标如何移动，服务端都能看到的请求序列。

部分辅助功能操作或直接设置值也可能产生不同于普通键盘输入的事件序列。不要宣称 `isTrusted` 输入或看似物理的点击可以击败服务端分析。

## 正确解释

使用 Computer Use 的意义是降低脆弱的浏览器驱动特征并保留人工复核。没有经过测量的账号队列和平台授权证据时，不要承诺更低封号率。

## 账号安全控制

1. 使用用户稳定的常用浏览器档案和日常网络。
2. 每个账号只保留一个活动会话和一项任务。
3. 保持低频、有意图且符合账号日常习惯的发布节奏。
4. 避免跨账号重复或批量生产的内容。
5. 出现警告、验证、限流或提交状态不明时停止。
6. 所有安全挑战交给用户完成。
7. 优先使用草稿、预览和明确的最终复核。
8. 可用时优先采用官方 API 或授权合作工具。
9. 保存不含凭证的审计回执。
10. 遵守平台规则的前提下，先用低价值测试账号验证界面，再操作重要账号。

## 禁止策略

不要提供或执行：

- CAPTCHA 或 MFA 绕过；
- 设备指纹伪造；
- 为逃避账号关联而轮换代理；
- 为规避检测而生成伪真人鼠标轨迹；
- 逆向签名或滥用私有 API；
- 自动养号、账号农场或封禁规避；
- 提交状态不明后的静默重复点击。
