# Markdown 到微信 HTML 的预览与发布门

本流程把 `md2wechat` 当作发布前排版器。默认只生成本地 HTML；除非用户明确授权，不创建微信草稿、不上传远程图片，也不调用远程生成服务。

## 1. 发现实时能力

先运行：

```bash
md2wechat version --json
md2wechat capabilities --json
md2wechat themes list --json
md2wechat prompts list --json
```

实时 CLI 输出优先于本 Skill 中的主题名称。不要猜测当前版本支持的主题、Provider 或 Prompt。

## 2. 区分目标

- 微信公众号普通文章：使用 `inspect`、`preview`、`convert`。
- 小绿书、图文笔记或多图消息：使用 `create_image_post` 路径；先用 `--dry-run`。
- 小红书、抖音等平台图文：使用图片卡片模板生成 PNG，再交给真实浏览器上传；不要把微信 HTML 当作图片帖子。

## 3. 本地排版

```bash
md2wechat inspect article.md
md2wechat preview article.md
md2wechat convert article.md -o review.html
```

选择自定义主题时，从 `md2wechat-article-templates.md` 复制完整主题合同给转换步骤。转换产物必须使用安全标签和内联样式。

## 4. 强制视觉审查

在浏览器中打开本地 HTML，并按移动端宽度检查：

- `ul/ol` 是否出现重复圆点、`$` 或其他装饰前缀；
- 代码高亮 `<span>` 是否嵌套错误，文字是否可读；
- 表头和隔行背景在渐变被过滤后是否仍清楚；
- 暗色引用块和代码块对比度是否足够；
- H1/H2 编号、竖线和徽章是否对齐；
- 图片是否加载、溢出、变形或顺序错误；
- 字体回退后是否造成标题截断；
- 链接、摘要、作者、封面和正文是否属于正确账号与文章。

发现问题后修复 HTML，重新预览。禁止把“渲染”和“发布”合并成一步。

## 5. 发布确认

向用户展示：

- 账号或公众号；
- 标题、作者、摘要和封面；
- 主题名称；
- 本地预览路径或截图；
- 所有排版检查结果；
- 将创建草稿还是执行最终发布。

没有明确授权时停在本地预览。即使用户授权自动填写，也要在创建远程草稿或最终发布前遵守主 Skill 的确认门。

## 6. 发布后核验

使用真实浏览器进入草稿箱或内容管理页，核对标题、封面、摘要、正文首尾、图片数量和当前状态。API 或 CLI 返回成功不等于前台排版正确。
