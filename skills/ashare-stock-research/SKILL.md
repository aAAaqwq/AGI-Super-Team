# A股个股投研（数据源 + 结构化报告工作流）

A股个股分析的标准工作流：**免费公开接口拉数（腾讯/东财/新浪）→ 计算技术指标 → 画K线图 → 输出结构化投研报告**。本 skill 收录实测可用的数据源、字段映射、反限流技巧与用户偏好的报告结构。

## 触发条件
- 用户要求"分析/看看 XX 股票"、问板块/题材归属、预测明日走势、持仓后问"割肉还是持有/怎么操作"
- 用户给出涨停/异动监控列表（作战池）问题材归类
- 用户给出买入成本价，要求针对性操作方案
- **持仓盯盘告警系统**（加/删盯盘票、改成本价、改提醒频率、提醒太吵、"阈值过期/每次都在推同一句"、盯盘脚本报错）
  → 走 skill **`position-alert-watchdog`**（cron no_agent + 动态阈值 + 每日去重）；本 skill 只负责提供行情/日K数据源。
- **问"怎么看大盘/成交量怎么读/竞价缩量放量/量能趋势/板块资金流向"** → 走 `references/market-volume-analysis.md`：必须用真实数据出判定阈值表 + 一个板块的实证（用户明确要求"拿科技来看"这类具象化），不能只讲空泛方法论。
- **问"换手率本质是什么/意味着什么"、个股高换手能不能跟** → 走 `references/turnover-rate-analysis.md`：先给本质定义 → 三维判定表（换手率×主力资金×价格六象限）→ 配他自己的持仓票实证。
- **问"如何精确判断主力资金走向/怎么知道是主力在买还是散户在接"** → 走 `references/main-force-capital-verification.md`：先破除"主力资金流是推算值"的幻觉 → 证据金字塔 → 龙虎榜席位性质 + 股东户数两大硬武器 → 同日对照实证。用户偏好在结论后追问方法论，主动把它做成可复用框架。
- **问"筹码分析 / 进出货 / 庄家资金强弱 / 会不会突破 / 还是洗盘出货"** → 用户明确点名的**五维框架**（缺一不可）：
  **① 筹码结构 → ② 主力进出货 → ③ 庄家资金强弱 → ④ 所属板块共振 → ⑤ 大盘**。
  筹码分布东财 `cyq` 接口已 404，改用**自建筹码模型**（价格网格 + 换手率衰减），
  算法/指标/实证全在 `references/chip-distribution-model.md`。
  ⚠️ **只罗列指标不给结论是无效输出** —— 必须落到「**突破 / 洗盘 / 出货**」三选一 + 概率 + 关键触发位，
  并给出可执行价位（上方压力 / 下方防线 / 减仓位）。
- **问\"财报出来了怎么看 / 业绩这么好为什么还跌 / 是不是利好出尽 / 明天财报落地怎么走\"**，
  或用户拿着**刚发布的季报·业绩快报**问涨跌 → **第一步不是读财报数字，是查「这份东西市场什么时候知道的」**，
  走 `references/earnings-announcement-verification.md`：公告列表 + 公告正文两个接口，把
  **业绩预告的发布日与预告区间**和**实际值**并排摆出来。
  **利好落地（预告早披露 + 实际值落在预告区间中部 = 零超预期）≠ 利好突发**，前者次日大概率"利好出尽"。
  ⚠️ **只看财报数字不看披露时点，会把"已知信息的确认"误判成"新催化" —— 结论方向直接反过来。**
- **问"能不能做 T / 今日怎么做 / 该不该现在挂单 / X 卖 Y 买回 / 挂单要不要等开盘"**，或给出**底仓成本价**
  要求降成本方案 → 走 `references/t-plus-zero-and-order-placement.md`：集合竞价挂单规则（9:15-9:20 可撤、
  9:20-9:25 **不可撤**、盘前挂 = 9:15 才报送）、限价单不会吃暗亏的价格优先原理、做 T 三前提
  （**必须有底仓**，A股 T+1；振幅 ≥2-3%；非单边下跌）、降成本数学、分档挂单 + 四条铁律、
  卖点窗口判定（用前30min占比识别「早盘冲高」形态）、
  **⭐ 昨日 VWAP 做中枢（含腾讯字段单位坑）+ 净收益 <30 元就不做 + 正T/反T 按外部变量选 + 破 MA10 不买回 + 竞价后条件化方案表**。
  ⚠️ **用户给成本价时必须先算浮亏 + 止损线（成本×0.95）并明确说「已破/未破」**；若已破线，
  先点破这一点再谈做 T —— 且**「反抽减仓」要排在「做 T」之前**，别让做 T 掩盖该止损的事实。
- **问"怎么看放量还是缩量 / 成交量怎么看 / 盘中怎么看订单/盘口分析涨跌 / 量比在哪看"** →
  走 `references/stock-volume-and-orderbook.md`：个股量能标尺（量÷5日/10日/20日均量 + 阈值表、
  换手率按市值分档、**盘中按时间折算或直接看量比**）、**放量≠好（位置×方向四象限）**、
  盘口订单分析（委比/内外盘/大单/逐笔 + 四种盘口陷阱 + 东财手机APP量比位置）。
  ⚠️ 用户偏好**具象化**：不能只讲方法论，必须配**他自己持仓票的真实数据表**做实证。
- **问"现在能不能买宽基 ETF / 有没有推荐 / XX ETF 的风险收益比如何 / 这个位置值不值得买"** →
  走 `references/index-etf-risk-return.md`：四步流程（定位 → 估值 → 趋势 → **历史条件回测**）、
  年化收益/波动/夏普/卡玛/最大回撤/回本时间的纯 Python 算法、**⭐ 回撤深度分层回测**
  （510300 实测：浅回撤 15-25% 档 1 年胜率仅 31%，35-50% 档才 94%）、趋势确认信号回测
  （站上周 MA20/MA30 +7~9pp，MA52 金叉无效）、持有期 vs 胜率表、标的分层口径。
  ⚠️ **"跌到新低"不等于"便宜"**：必须同时报「近 250 日分位」和「历史 10 年+分位」两个尺度
  （实测 510300 一年新低 = 11.7 年的 63.7% 分位，一点都不便宜）。
  ⚠️ **禁止只看位置就下"可以分批买"的结论** —— 必须先跑回撤分层回测拿到历史胜率，再谈仓位。
- **问"有没有周期性 ETF / 要一个当前处于周期反弹上涨阶段的 / 今天建仓哪个 ETF 好、什么价入 / 结合新闻面和商品走势看走势"** →
  走 `references/cyclical-etf-screening.md`：**三维判据**（站上全部均线 + 对应商品期货在涨 + 板块龙头共振，缺一不可）、
  22 只周期 ETF 代码池 + 商品期货代码对照（`nf_XX0` 内盘 / `hf_XX` 外盘）、
  **⭐ 成分归因法**（ETF 跌但同主题单一商品 ETF 涨 ⇒ 跌幅来自另一部分，是可解释低开不是逻辑坏了）、
  三批建仓 + 跳空调整表、**宽基 ETF 不设价格止损 / 单一行业 ETF 必须设**的口径区别、新闻面五层框架 + 概率化情景。
  ⚠️ **"跌 39%"的有色/光伏不是"周期反弹"，是下跌趋势** —— 三维不满足就明说不碰。
  ⚠️ **银行 ETF 不是周期股**（红利逻辑），用户要商品周期时别拿它凑数。
- **问\"被套了，反弹回成本线要多久 / 还有没有机会回本 / 亏这么多要不要等\"** →
  走 `references/breakeven-time-calculation.md`：先算 `回本需涨 = 成本/现价 − 1`（**跌 30% 要涨 43%，
  非线性**），再跑 250 个起点的「首次达标耗时」分布，输出**三件套**：
  `需涨 X% | 中位 N 日 | 250日内达成率 Y%`。
  ⚠️ **⭐ 只报中位数就是骗人** —— 中位数只统计成功样本（示例股C实测：中位 20 日，但达成率仅 31%）。
  ⚠️ 结论要给「时间/机会/心理」三层成本 + **分批+死线**，不要一刀切（用户会讨价还价"真得完全割吗"）。

## ⭐ 选股流程（问「选几只优质股 / 明天哪个有机会 / 有没有有主力的」时）

完整框架在 skill `youzi-stock-quality-screen`（五标准 + 量价四象限）+ `ashare-volume-resonance-analysis`（四维共振）。**本节只记录三条被用户当面纠正过的硬规则** —— 无论走哪个框架，这三条必须遵守。

### 规则 1：**可买性是第一道闸，买不进的一切筛选都是白做**

> **用户原话：「根本买不进选的没用呀」** —— 2026-10-26 按框架选出三只全封死一字板（上海九百封单 11.25 万手、多伦科技 39.7 万手、卖1-3 全为 0），次日全部涨停但一股买不到。

| 指标 | 🟢 买得进 | 🔴 买不进 | 取法 |
|---|---|---|---|
| **封单金额** | **≤ 0.5 亿** | > 2 亿 | 东财涨停池 `fund` |
| **换手率** | **8-20%** | < 3% | 东财涨停池 `hs` |
| **量比** | **> 1** | < 0.5 | 腾讯 `[49]` |
| **炸板次数** | 0-2 次（说明会开） | 一字板且换手<1% | 东财涨停池 `zbc` |
| **卖1-5 挂单** | 有量（>100 手） | 全为 0 | 腾讯 `[19]~[28]` |

**口诀**：封单越小越能开、换手越高越能进、量比越低越买不到。**一字板 + 卖盘为 0 = 只能看不能做。**

⚠️ **先把这一层过掉再谈其他维度**。反过来，如果一只票「五标准全过但封死」，正确输出是**明确说买不进**，而不是把它当推荐。

### 规则 2：**开板了，是「分歧」还是「出货」——只看能不能快速回封**

| # | 判据 | 🟢 分歧（洗盘，可进） | 🔴 出货（派发，别碰） |
|---|---|---|---|
| **1** | **开板后能否快速回封**（最关键） | **5-15 分钟内回封** | 迟迟不回，或收盘没回 |
| 2 | 开板最低价距涨停价 | **−2% 以内** | **−5% 以上** |
| 3 | 开板时量能 | 温和（< 封单量 30%） | **突然放天量** |
| 4 | 回封后量能 | **缩量**（锁住） | **持续放量**（还在换手） |
| 5 | 炸板次数 | **1-2 次** | **3 次以上** |
| 6 | 当天资金流 | 净流入 | **大额净流出** |

**本质**：分歧 = 卖的人少买的人多 → 快速回封 → 筹码从弱手换到强手；出货 = 主力想卖的量 > 接盘量 → 越走越低回不来。
**口诀**：**开板不可怕，「开板后回不回得来」才是关键。**

**竞价阶段只能给倾向**（卖1-5 极薄 + 外盘 >75% + 低开 <2% → 偏分歧；卖2/卖3 压数千手 + 外盘 <50% + 低开 >3% → 偏出货），**必须等 9:30-9:45 真实回封行为确认**。

**⚠️ 顺带识别「内外盘背离」**：挂单很厚（买1 数千手）但内盘是外盘 3-4 倍 = **托单诱多**，挂单是假的、砸盘是真的。2026-10-26 实测示例股A竞价内/外盘 4.3:1、示例股F 3.9:1，当天分别 −9.40% / −7.65%。

**实战对照**：2026-10-27 东方海洋/秦安股份/襄阳轴承均炸板 1 次后 3-7 分钟回封 → 六判据全属真分歧（但封单 12.9-51.6 万手，当天仍买不进，见规则 1）；兰生股份开盘封 9.02 → 砸到 8.56 全天未回 + 天量 9.2x → 全指向出货。

### 规则 3：**永远不要承诺「必涨」**

用户会问「明天必涨的是哪个」。**必须当场拒绝这个提法，改成「概率 + 触发条件 + 失效条件」**：

- 先泼冷水：「没有任何方法能保证必涨」
- 报一个自己的概率估计（**弱势环境要压低，如 40-55% 而不是 70%**）
- 给「今天必须发生什么，明天才算有戏」的验证条件（如「海洋王今天封住涨停，明天才有溢价；封不住都是空谈」）
- **查市场宽度再说结论**：涨跌比 <1:2 → 所有追涨建议打折；<1:3 → 只减不加。2026-10-27 实测 1156 涨 vs 4303 跌（1:3.7），当天所有追涨结论都该附这个前提。
- 如果自己的系统（龙擎）`high_prob` 全为 false / 数据 `DEGRADED`，**如实告知**，别包装成有信心。
- **⭐ 给「明天可接力」的建议前，先看今天的高位股是否在批量崩塌**：若当天有 **≥2 只 4 板以上票跌停**，
  所有接力/连板建议作废，改「防守/减仓」口径。2026-11-16 实测：东方环宇（5板）、锋龙股份（4板）、
  大东方（4板）、日盈电子（前一日刚涨停）同日全部跌停，当日跌停 60 只 > 涨停 32 只、创业板 −4.37%。
  **配套教训**：系统分/首板强度只能选「当天」，不能预测「次日」—— 日盈电子当时龙擎加权分池内第一
  （0.842）、推荐后 40 分钟内封涨停，**次日仍直接跌停**。决定次日存活的是**位置**（距 MA30），不是分数。

### 规则 4：**追高禁令 —— 乖离 MA5 > 10% 不许给买点**

> **事故（2026-10-28）**：示例股B 600000 我写「现价可小仓」，用户冲到 **12.70** 买入 —— 那是当日最高 12.71 附近，**全天只有 3 分钟价格 ≥12.70**。当时乖离 MA5 已达 **+11.87%**（健康区间 3-8%），属严重透支。

| 乖离 MA5 | 判定 | 动作 |
|---|---|---|
| **0 ~ +8%** | 🟢 健康上涨 | 可给买点 |
| **+8% ~ +10%** | 🟠 偏热 | 只能小仓，且**必须写明「回踩 MA5 再进」** |
| **> +10%** | 🔴 **透支** | **不给多头建议**，只给「等回踩」或「已持仓减仓」 |

**配套的日内买点纪律**（写进任何盘中建议）：
- 不追当日涨幅 > **+5%** 的票（除非是 skill `main-force-prelaunch-pattern` 定义的「确认启动」放量突破）
- 必须报 **「现价距今日最高 X%」**；< 0.5% 就是买在最高点，要明确说
- 分时只能给倾向时，也要给「什么价位才算好买点」，不要只说「可以小仓」

**本质**：乖离大 = 短期成本高于市场平均太多，回踩 MA5 是均值回归的必然。**追高不是勇敢，是把胜率让给对手。**

### 规则 5：**成本必须用用户给的明确数字，不许自己推**

> **事故（2026-10-29）**：用户说「示例股B买了 12.7」，我按 12.70 算 → 报告「+2.83% 盈利」。用户发来持仓截图，实际成本 **13.527**（后来加过仓），真实是 **−3.60% 亏损** —— **盈/亏方向都算反了**。

**规则**：
1. 用户报成本 → **只用这个数字**，不推、不假设、不「按之前说的」。
2. 用户发持仓截图 → **逐字取**（持仓量 / 可用量 / 现价 / 成本 / 盈亏额），不沿用对话里的旧成本。
3. 疑似加仓/摊薄 → **主动确认「成本是 XX 吗，我按新成本重算」**，不默默沿用。
4. 发现自己算错 → **立刻明确纠正 + 重算全部相关数字**（含盈亏额、止损位、减半后的亏损额）。
5. 每份持仓分析开头列一行 **「成本 / 持仓量 / 来源（口述 or 截图）」**，保证可追溯。

## 报告结构（用户偏好，按此顺序输出）
用户期望中文报告固定骨架：
1. **标题**：股票名 + 代码 + 分析日期 + 现价/涨跌
2. **新闻面表格**：日期 | 事件 | 信号(🚀催化/⚠️利空/💎业绩/🔄分歧)，含近期关键催化
3. **产业逻辑**：业务卡位、行业景气逻辑，⭐给强度评分，指出基本面 vs 题材
4. **板块共振**：列出同板块 5-6 只同行涨跌/换手对比表——**判断是板块行情还是独立行情**（同行都不动只有它放量=游资独立炒作，风险高）
   - ⚠️ **反向信号更要重视：板块齐涨、唯独它跌 = 个股在派发，不是"板块退潮"** ——
     此时别拿"板块还行"给自己安慰。实测案例：PCB 板块生益科技 +3.94% / 胜宏科技 +1.28% /
     沪电股份 +1.11%，而持仓票 **-2.08% 独跌** ⇒ 结论是个股出货、按纪律止损。
   - 务必配合主力资金看：**净流入连续递减直至单日转负**（实测 +15.98亿 → +6.41亿 → +3.81亿 →
     +1.56亿 → +0.84亿 → **-0.06亿**）是派发的标准曲线，比单看当日涨跌幅可靠得多。
   - 用户给的**成本价要先算出止损位**（成本 × 0.95）并与现价对照，**明确说出"已破/未破"** ——
     用户自定纪律是硬约束，不要用"还有支撑"之类的话术软化它。
5. **个股技术形态**：近期走势复盘（关键高低点日期）、MA5/10/20/60、MACD DIF/DEA/柱、RSI14、量能、均线多头/破位、支撑压力位（含涨停/跌停价）
6. **走势预测**：分基准/乐观/悲观三情景 + 概率
7. **操作建议**：分情景给策略；若用户给了成本价，**先算浮盈/浮亏**，按强弱给止损止盈铁律；高位妖股原则=反弹离场不补仓、破位止损
8. **一句话结论**
9. **风险提示**：非投资建议 + 高换手游资风险
10. **MEDIA:** 附图（K线图路径）

## Pitfalls
- **⚠️ 「位置低」不等于「该买」—— 下结论前必须跑一次历史条件回测**：本会话看到「创业板/中证1000/沪深300 全在 250 日最低点、PE 13」就给了「可以分批买 30%」的偏乐观建议；随后按**回撤深度分层回测**发现该档位（−15~−25%）历史上 1 年胜率只有 **31%、中位收益 −8.9%**，真正的高胜率区（94%）要跌到 −35% 以下。**"跌了这么多"是直觉，不是依据。** 凡是回答「能不能买/什么位置买」，先给出**同档位历史胜率**再谈仓位，否则就是拿感觉当分析。同理：「一年新低」也要和「10 年分位」一起报（实测 510300 一年新低 = 11.7 年的 63.7% 分位）。
- **腾讯行情 GBK 编码**：`qt.gtimg.cn` 返回 GBK，必须 decode('gbk')，否则中文乱码/报错。
- **东财搜索是 jsonp**：返回 `cb({...})`，json.loads 前必须剥壳。
- **东财财务金额单位是元**：记得 ÷1e8 才是亿，报告里标"亿"。
- **push2his 资金流限流严重**：连续多股查询必 429 或 Remote end closed，每股之间 sleep 3-5s，失败换新浪。
- **东财数据中心 filter 引号**：日期值用 `'2026-09-02'` 单引号，代码用双引号 `"002104"`。
- **判断连板数**：靠新闻（"XX 9天5板"），不是简单数 K 线红盘。
- **⚠️ 容器时钟可能偏差数天，连 `date` 都不可信**：实测容器 `date` 显示 `2026-09-14 09:16`，
  而行情时间戳是 `20260915131141`（**9/15 13:11**）—— 差了一整天，还落在完全不同的交易时段。
  **开工第一步永远是：拉一次行情 → 读 `[30]` 时间戳 → 据此确定"今天几号 + 现在是否盘中"**，
  再决定报告口径。`datetime.now()`、`date` 命令、会话开头标注的日期都**不能**作为判断依据。
  - 踩坑代价：误判成「盘前」，于是按"预测今日走势"组织报告，实际已在盘中，
    而且用户问的票**当天已跌破他自己定的止损位** —— 结论方向完全错，用户要的是"现在怎么办"。
  - 同理，K 线最后一根的日期（若已含今日）也能佐证"今天是不是交易日、是否在盘中"。
- **系统容器时钟可能非北京时间**：分析"今日/昨日"边界时以行情时间戳（`[30]`）或 K 线最后日期为准，不要用 `datetime.now()` 裸判断。
  - **容器时区实测为 UTC（`date +%Z %z` → `UTC +0000`），北京时间 = UTC + 8h**。这一条本会话连续踩两次：
    容器 `date` 报 `2026-10-08 10:24 UTC`，实际已是北京 **18:24（当日盘后）**，差点按"盘中"作答。
  - **NAS 文件 mtime 是北京时间，容器是 UTC，两者天然差 8 小时** —— 别拿"NAS 文件时间是 18:23"
    去反推容器时间，会得出"现在 18:23"而容器说 10:24 的矛盾。**以行情时间戳为唯一锚点。**
  - 判断顺序：① 拉行情读 `[30]`（北京时间）→ ② 若时间戳停在上一交易日收盘（如 16:14），
    说明**当前非交易时段**（盘前/盘后/假期）→ ③ 用 `minute/query` 的 `date` 字段确认最新交易日 → ④ 再决定口径。
- **高位妖股特征**：连续涨停+换手 20%+→ 见顶信号（冲高长上影/天量/主力净流出/龙虎榜净卖/北向卖出）→ 次日常跌停/低开；操作建议倾向"反弹离场、破位止损、不补仓"。
- **⚠️ 财报大超预期 ≠ 利好。先查预告日期，再谈利好利空**：2026-10-27 示例股A三季报 Q3 单季净利
  同比 **+276.24%**，看着像爆炸性利好；但 **10-13 就发过业绩预告（+90.78%~+102.00%），实际 +97.52%
  正落在区间中部 = 零超预期**，而且 10-13/10-14 已经两个涨停把这件事定价完了。当天盘面 **−4.81%**，
  之后是"利好出尽"。**教训：财报数字本身没有信息量，「数字 − 已预告的区间」才是信息量。**
- **⚠️ 缩量下跌有三种，别一律当洗盘**：① 缩量**横盘**、重心不破 = 洗盘；② 缩量**阴跌**、
  连跌数日跌破全部均线 + 主力连续净流出 = **派发尾声的失血**（主力已经卖完，不需要再供量，
  价格靠"没人接"自然滑落）；③ 缩量涨停封死 = 锁仓。判别只看两条硬证据：**资金流方向**和
  **筹码获利盘**（失血时获利盘已剩个位数 %）。详见 `references/chip-distribution-model.md` 的
  「洗盘 / 派发 / 失血 三态判定表」。
- **⚠️ 「净流出累计 > 前次拉高净流入」= 派发确认，比任何指标都硬**：超声实测 10-20 净流入 **+8.00 亿**
  把股价顶到二次顶（未破前高 = 双顶形态），之后 5 日净流出 **−9.30 亿**（超大单 −6.38 亿）——
  不但把那次拉高的钱全反手卖掉，还多卖了 1.3 亿。**这种"流入一次、流出更多"的结构出现，
  就不必再找别的理由了。**
- **⚠️ 破线后别再谈"还有支撑"**：用户成本 × 0.95 = 纪律线，**首次收盘跌破就要报"已破线 N 个交易日"**，
  并把超出的百分点算出来（超声 22.97 破线，10-22 首破，回答时已破 4 日、超出 24.7pp）。
  用户会讨价还价，正确做法是**先点破"止损已经迟了几天"，再给分批+死线**，而不是软化。

## Pitfalls（续）
- **腾讯 K 线字段顺序是 `[date, open, close, high, low, volume]`，不是 OHLC**！把 `[3]` 当最高价会全盘算错（本会话踩过）。索引：0=日期 1=开 2=收 3=最高 4=最低 5=成交量(手)。
- **腾讯 `day/query` 近5日分时是倒序**（最新在前），算环比必须先反转，否则"昨日"取到的是更早那天。
- **东财 push2his（K线/资金流/板块）限流阈值极低**：连查几次后整批 RemoteDisconnected，重试+sleep 也无效，需等较久。分析主链路走腾讯，东财只做补充。
- **画图中文乱码**：系统已装文泉驿正黑，不设则中文全是方框。**但 matplotlib 版本差异要兼容**：
  3.11+ 已移除 `matplotlib.font_manager.addfont`（会报 `AttributeError: module 'matplotlib.font_manager' has no attribute 'addfont'`），
  改用 `font_manager.fontManager.addfont(path)`。稳妥写法：
  ```python
  from matplotlib import font_manager as _fm
  p = '/usr/share/fonts/truetype/wqy/wqy-zenhei.ttc'
  ```

- **新浪 `MoneyFlow.ssl_qsfx_zjlrqs` 返回的是标准 JSON，不是 JSONP**！直接 `json.loads()` 即可。不要用\"给裸 key 补引号\"的正则去修它，会把数组/嵌套类型弄坏报 `Expecting ':' delimiter`（本会话踩过）。
- **新浪 `newSinaHy.php` 是 GBK**，且返回 `var S_... = {...}` 前缀，需剥壳后 json.loads。
- **算历史换手率序列时分母别用总股本**：用 `流通市值÷现价` 得流通股本。只有全流通股两者才等价；口径错了整条换手曲线都会偏，妖股尤其明显。
- **东财 datacenter-web 返回 400 Bad Request 的根因通常是 filter 写法，不是服务挂了**（本会话最初两只票全 400）：① 去掉日期 filter，改用 `&sortColumns=TRADE_DATE&sortTypes=-1` 查最近 N 条；② filter 值 `urllib.parse.quote` 后再拼 URL；③ 带上 `&source=WEB&client=WEB`。按此改写后连查龙虎榜/席位/股东户数/大宗交易 6 个报表全通。仍失败再转"东财新闻搜 `XX 龙虎榜`"兜底。
