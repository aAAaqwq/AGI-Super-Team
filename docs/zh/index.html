01 / 从意图到行动

你给出目标。
团队负责手艺。

研究员找证据，设计师塑造体验，工程师把它建出来。共享的指令让彼此的工作衔接得上。

你的目标 / 示例
“帮我把「客户反馈工具」的想法，变成一个可测试的小型 MVP。”
产品交付团队
可复核的交接
  • 01一份有边界的产物定义用户是谁、问题是什么、先做什么。
  • 02一个带检查的原型聚焦的实现，加上可复现的测试。
  • 03一个你能拍板的决定审查结论、已知限制，以及下一步。
  1. 01

    框定工作。

    CEO（首席执行官）把目标拆成结果，选出小团队，并说清验收标准。

  2. 02

    让专家专注。

    每个角色负责一件有边界的事，调用相关 Skill，再把成果带回共享计划。

  3. 03

    先审查，再决定。

    Governor（独立复核）质询证据。你审阅产物，并批准任何发布或对外动作。

仅为流程示意，不是已交付的项目。AGI Super Team 提供角色指令与打包，实际执行由你的 Agent 框架完成。

02 / 有边界的并行

发起蜂群。
保持单一归属。

有些工作天然可拆：多角度评审、难缠的 Bug，或者彼此独立的功能切片。Swarm agents 在同一个协调者下并行推进这些工作流，再把证据汇总回来。

触发方式 / 示例
“Swarm agents: 从安全、性能和 API 契约三个角度评审新的限流器。”
评审蜂群 · 3 个执行者
你会拿到什么
  • 01一个文件只有一个负责人不会有两个 Agent 写同一个文件路径。
  • 02结论带证据每条判断都附上它背后的文件、命令或测试。
  • 03一份汇总后的答案协调者合并结果、标出冲突，并跑完检查。
  1. 01

    说出触发语。

    Swarm agents: <你的目标> 会把目标路由给一支小团队，而不是拉成一条长对话。

  2. 02

    划定边界。

    每个执行者只拿一个目标、一组自己可写的文件、一条验收标准；默认 2–3 个。

  3. 03

    汇总。

    父 Agent 合并结果、解决分歧，并在任何东西交付前跑完测试。

触发语只是路由提示，不代表无限并发。并发数、嵌套深度、工具与模型权限，由你运行的框架决定。

04 / 变成你自己的

你的框架。
一种新的工作方式。

从一份被检查过的仓库副本开始。选择你的框架，先预览它要写入哪些文件，再决定是否安装。

需要 Git 与 Node.js 18+。你的框架可能要求更新的 Node.js 版本。

源码与 npm：1.8.0
下面的命令使用仓库副本；对应的 npm 版本已经发布。 发布详情。

阅读适配器指南 ↗
CLAUDE CODE / 预览
git clone --depth 1 --branch main https://github.com/aAAaqwq/AGI-Super-Team.git
cd AGI-Super-Team

# 先检查仓库副本，再预览。不会写入任何文件。
node bin/agi-super-team.mjs --tool claude-code
默认只预览，安装需要显式执行。
看完预览，准备安装了？

在同一份仓库副本里，加上 --install --connect，再单独跑一次 --doctor 检查。把 claude-code 换成你选的框架 ID。安装会写入受管的 Agent 与 Skill 文件；连接步骤可能修改框架配置。请保留它报告的备份，用于还原被替换的文件。Hermes 只生成 blueprint。

node bin/agi-super-team.mjs --tool claude-code --install --connect
node bin/agi-super-team.mjs --tool claude-code --doctor

打开一个新的客户端会话，看看它发现了什么。Doctor 检查产物，不检查模型行为。

想要不绑定具体框架的工作区？先预览 Solo Founder

从仓库副本出发，预览一个独立的工作区。先看清目标目录与文件计划，再加 --apply。

./install.sh --source "$PWD" --destination /path/to/review-workspace solo-founder
